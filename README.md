##Git Workflow & Branching Strategy

Our development followed a feature branch workflow with Pull Requests and Peer Reviews:

1. Main branch reserved for stable releases (`main`).
2. Isolated feature branches created for specific task implementations.
3. Pull requests required code review and approval before merging.
4. Resolving intentional merge conflicts locally before pushing.

### Branches Used
* `main` - Stable main branch
* `feature/task-form` - Task input form interface
* `feature/task-style` - Custom UI styling and layout enhancements
* `feature/task-search` - Task searching functionality
